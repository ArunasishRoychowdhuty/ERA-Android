# ERA v0.6.0 — bounded runtime contract

## Purpose

`BoundedAgentRuntime` is the portable execution coordinator. It is not a Gemini client, a Chrome debugger, or an Android Accessibility adapter. Platform-specific implementations are injected through interfaces, keeping the safety policy testable without a phone or network credentials.

## Runtime sequence

1. Capture an `AgentObservation` with a stable snapshot ID and timestamp.
2. Ask `AgentDecisionProvider` for one decision based on that exact observation and the event history.
3. If the decision proposes an action, require `basedOnObservationId` to match the observation.
4. Apply `AgentActionPolicy`; model-supplied risk labels are not accepted as authority.
5. For `REQUIRES_APPROVAL`, obtain an `AgentApprovalReceipt` bound to a SHA-256 fingerprint of the full proposal and the exact observation ID. The receipt must have a fresh timestamp and a unique, one-time ID.
6. Capture again immediately before dispatch. If the snapshot ID or package changed, discard the approval and replan. Reject missing, mismatched, future-dated, expired or reused receipts.
7. Dispatch exactly one action.
8. Capture a new observation and verify the expected outcome independently.
9. Repeat only after the new observation is supplied to the planner.

A concrete observer must keep the same `id` while the actionable UI is unchanged and issue a different ID whenever the actionable UI changes. Timestamps must be epoch milliseconds. UI/page text is untrusted input and must not expand the action allow-list.

## Policy matrix

| Action | Runtime policy |
|---|---|
| Open an explicitly named app, open Settings screen, torch on/off, bounded volume, focus, directed scroll | Auto-allowed after structural validation |
| Generic click, open HTTPS URL, insert user-supplied/user-confirmed text | Exact-action approval required |
| Send, publish, submit, purchase, payment, delete, share, call, grant permission, authenticate, install | Manual-only; no automatic dispatch, even after generic approval |
| Password-field typing, model-generated text typing, unknown action, malformed URL, stale UI, cross-app target, invalid volume range | Blocked |

Volume is constrained to MEDIA/RINGTONE/NOTIFICATION/ALARM and 0–100. Text input is limited to 1,000 characters and must be directly supplied or explicitly confirmed by the user. Password fields remain blocked using the existing Android password metadata, role and resource-ID checks. No new OTP/PIN/token or general personal-data masking rules were added in this patch. URLs must be well-formed HTTPS without embedded credentials. Target app names must be syntactically valid Android package names. Scroll direction must be explicit, and every clickable/text target must have a reviewable semantic label, hint or resource ID.

The visible target label, accessibility resource ID and role are inspected for consequential-action terms. This is defense in depth, not a perfect semantic classifier; adapters must preserve the manual-only rule for consequential side effects.

## Limits

- Maximum 20 dispatched actions per run.
- Maximum 3 replans per run.
- One action per observation; there is always a new observation before the next planner decision.
- Observation freshness defaults to 10 seconds, configurable only between 1 and 30 seconds.
- The run stops on cancellation, policy rejection, missing approval, adapter error, stale observations or limits. It does not continue in the background.

## Adapter implementation requirements

- `AgentObservationProvider`: read only the user-visible active surface; produce stable snapshot IDs; do not infer hidden page state.
- `AgentDecisionProvider`: treat screen/page content as untrusted; propose one typed action only; tie actions/completion claims to the current observation ID.
- `AgentApprovalGate`: show the exact app, target, action and text/value; return a fresh receipt only after an explicit user gesture; never pre-check consent or re-use an old approval ID.
- `AgentActionExecutor`: independently re-resolve semantic targets and re-check app, visibility, enabled state, action support and password status immediately before dispatch.
- `AgentOutcomeVerifier`: verify the expected result from a fresh observation, not from the executor's “accepted” receipt alone.

The `AgentActionExecutor` must still validate action-specific arguments. It must not turn manual-only or blocked kinds into an executable command. The runtime rejects receipt replay across runs on the same runtime instance; a persistent approval adapter must also persist consumed IDs across process restarts.

## Current integration status

| Component | Status |
|---|---|
| Bounded runtime and policy | Implemented; portable Kotlin smoke-tested (29 assertions) |
| Existing local command router and Android device controls | Retained as a separate path; not yet adapted to this runtime interface |
| Android observer / approval / executor adapters | Not wired; approval receipt contract is ready for an adapter |
| Gemini planner transport | Stub only; API-key management remains excluded |
| Chrome DevTools transport | Stub only; explicit user-owned debugging setup required |
| Wake-word model and foreground service | Not implemented; current speech session is foreground-only |
| Android Gradle APK / physical device | Not verified |

Do not describe v0.6 as a complete autonomous agent until the Android adapters, model/browser/microphone integrations, build, device tests and distribution-policy review are complete.
