# v0.7.1 — one-time permission setup

## User experience

ERA presents three separate access states in the Permission Center:

| Access | Needed for | Setup |
|---|---|---|
| Microphone (`RECORD_AUDIO`) | Speak and foreground voice session | Android runtime permission dialog |
| Camera (`CAMERA`) | Flashlight / torch control | Android runtime permission dialog |
| ERA Screen Inspector | Local Accessibility-tree observation and approved UI actions | User accepts the in-app disclosure, then manually enables the service in Android Accessibility Settings |

No permission dialog is shown on app launch. A runtime dialog is requested only when the user explicitly starts a feature or taps that permission's setup button, and only while Android reports the permission missing. Once granted, all feature entry points check the live Android grant and do not launch the dialog again.

## Source of truth and persistence

Android is authoritative. `MainActivity.refreshPermissionStatuses()` checks `RECORD_AUDIO` and `CAMERA` through `ContextCompat.checkSelfPermission()` and obtains Accessibility status through `AndroidCapabilityDiscovery`. The check runs on app creation and every `onResume()`. Grant state is intentionally **not** persisted in app preferences; storing a cached `true` would be incorrect after a user revokes access or Android resets unused-app permissions.

The permission result is routed according to the user-initiated operation: permission setup only updates status, voice input starts only the selected speech feature, and a pending flashlight command resumes only after Camera access is granted. A denied permission leaves that feature unavailable; text commands and other features remain usable.

## Important Android behaviour

- For microphone, Android can offer `Only this time`. That grant is temporary. When the user intends to grant ongoing app use, choose the ordinary `Allow` option instead. ERA cannot force the system's choice or turn a temporary grant into a persistent one.
- Even a regular grant can later be revoked by the user, reset by Android's unused-app permission protection, or removed by uninstall/reinstall. If Android reports it missing, ERA asks again only when the relevant feature is explicitly used.
- Accessibility is not a standard runtime permission. Android requires the user to enable the named service in system settings. ERA does not and cannot silently enable it. The state is refreshed when the user returns to the app.
- The current voice-recognition session stops when ERA leaves the foreground. This revision does not implement an always-on microphone or wake-word service.
