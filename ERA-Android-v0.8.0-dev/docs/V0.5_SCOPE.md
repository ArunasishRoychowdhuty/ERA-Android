# ERA v0.5.0 scope and honest implementation status

This revision adds interfaces/scaffolding, not a fully running autonomous agent.

## Selected direction
- AI brain: Gemini, but provider transport is not wired. The API-key security-management work remains excluded, so the scaffold deliberately has no key storage or network call.
- Browser: Chrome via a user-configured Chrome DevTools Protocol (CDP) session. Android Chrome's private DOM is not exposed by an ordinary app API; this bridge is a contract/stub only.
- Wake word: foreground-visible microphone session only. The engine is a stub; model/runtime and lifecycle integration remain pending.
- Autonomy policy: bounded step/replan limits, one action per observation, confirmation for consequential action names.

## Implemented in this scaffold
- Provider, browser-bridge, and wake-word interfaces.
- Action confirmation policy and run limits.
- Explicit stubs fail rather than pretending they are operational.

## Not implemented / not tested
- Gemini API transport and model responses.
- Wake-word model, continuous detection and Android foreground service.
- Chrome CDP transport, pairing/configuration and DOM action dispatch.
- Complete autonomous loop, real device end-to-end tests, Android build.

## Chrome prerequisites (manual/user-owned setup)
Chrome DevTools automation generally requires a user-configured debugging session (commonly ADB port forwarding from a desktop). This app does not silently enable Chrome debugging, bypass lock screens, or connect to arbitrary browser targets.
